# ADR 0001：拆分为 Core / ViewModels / App / Tests 四个工程

- 日期：2026-09-01 ｜ 状态：已采纳

## 背景
单工程 13k 行，纯逻辑与 WinUI 混在一起；任何逻辑验证都得启动 GUI，只能靠 CLI 自检（需真实 dsh/端口/WSL）。
另有一个嵌套的工程副本被 SDK 默认通配符吸进主工程，导致 900 个"重复定义"错误、主工程根本构建不了。

## 选项
1. 维持单工程，靠目录约定分层——无法机检，逻辑仍不可测。
2. 拆 Core 类库 + App —— 逻辑可测，但视图模型仍在 WinUI 工程里，UI 逻辑依旧不可测。
3. 再拆一个 ViewModels 工程（本决策）。

## 结论
四工程。Core 与 ViewModels 都是 `net10.0`，可被 xUnit 直接引用；App 只剩 XAML 与控件事件。
Core 对 UI 的唯一依赖（DispatcherQueue）抽象为 `IUiDispatcher`。

## 后果
- 离线断言从 0 涨到 153 条，秒级反馈；两个真实并发缺陷正是被这些测试抓到的。
- 代价：多两个工程文件与一次引用方向的约束（由机检守住）。
